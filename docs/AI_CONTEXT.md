## Relationships: physical versus logical

`database/schema/ai-structure.sql` is generated by applying every migration to a
fresh SQLite in-memory database. It contains table/column/index/constraint
definitions only. It is not a production MySQL schema dump or restore script.
Migrations are the source of truth, including driver-specific changes.

| From | To | Relationship and caveat |
| --- | --- | --- |
| users.contributor_id | contributors.id | Logical unique optional link; Contributor::user() is hasOne. Access is checked by controllers/middleware. |
| attendances.user_id, daily_work_reports.user_id | users.id | Logical owner; unique (user_id, work_date) prevents duplicate daily entries. |
| attendances.contributor_id, daily_work_reports.contributor_id | contributors.id | Logical contributor reference plus historical contributor_name snapshot. |
| studio_recordings.assigned_contributor_id | contributors.id | Logical optional assignment; assigned_worker_name preserves history after deletion. |
| payslips.employee_name, payroll_statuses.worker_name | contributor name / recording assigned_worker_name | Legacy name-based association, not a guaranteed foreign key; renaming and duplicate names need care. |
| device_accounts.phone_key, daily_work_reports.phones / phone_durations | DailyWorkReport::PHONES | Shared enum-like keys for six phones, not a phones table. JSON values require controller validation. |
| shift_days.config, shift_settings.setting_value | ShiftConfiguration / ShiftSchedule | JSON schedule snapshots and routine fallback; not relational joins. |

Do not invent foreign keys or Eloquent relationships that are absent from source.
External account emails and name-based matching are lookup rules, not enforced joins.

## Bug investigation and invariants

- Start with a narrow graph query (budget 800–1500), then inspect the located
  methods, route middleware, validation and relevant test. Use `affected` for
  impact analysis. Confirm inferred edges in source before changing behavior.
- Contributor identity comes from the authenticated account, never a submitted
  user_id/name. Admin routes require EnsureAdministrator and active-account checks.
  Personal payslip/file routes require ownership validation as well as login.
- Business dates and payroll periods use Asia/Makassar (WITA); timestamps may be
  UTC. Payroll cutoff is 22–21; check PayrollPeriod and payroll config.
- Payroll uses approved recording minutes and bonus; attendance/report durations
  are not automatically payable hours. Historical slips and live calculations differ.
- Daily reports include aggregate duration and per-phone JSON durations. Inspect
  DailyWorkReportController validation rather than assuming duration is wall time.
- Date-specific shift/report revision checks protect concurrent edits. Preserve
  snapshots and test stale-revision conflicts.
- Sync should preserve manual assignments/payment status/notes. Validate parsing
  against fixtures, without calling external services merely to investigate a bug.
- Never index .env, storage, credentials, account records, GPS records, SQL data
  dumps, PDFs/evidence or production logs. No seed/import/sync/restore on live data
  as part of graph maintenance.

Graphify cannot prove the absence of bugs. Its AST may miss Laravel facade calls,
dynamic routes, container resolution, Blade/Alpine bindings and logical JSON/name
joins. A missing graph edge is not evidence that code or a relationship is unused.
